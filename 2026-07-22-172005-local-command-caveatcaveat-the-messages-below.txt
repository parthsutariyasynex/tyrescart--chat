● Here's a proper explanation of loadGraphQLProducts — the search/fetch function
  for products (app/dashboard/products/page.tsx, lines 99–168).

  Purpose

  It's the single function that loads the product grid. It runs on first mount
  and re-runs automatically whenever the search term, brand tab, or page changes
  (that's the dependency array on line 168). It's cache-first: it paints
  instantly from IndexedDB, then refreshes from Magento in the background.

  Step by step

  1. Clear any previous error (line 100)
  setError(null);
  Starts each load with a clean slate so an old error banner doesn't linger.

  2. Build the search term (lines 105–107)
  const terms = [activeBrand === "All" ? "" : activeBrand, debouncedSearch]
    .filter(Boolean)
    .join(" ");
  - Combines two inputs into one Magento search string: the active brand tab and
  the debounced search box text.
  - activeBrand === "All" → contributes "" (no brand constraint).
  - .filter(Boolean) drops the empty pieces, .join(" ") merges what's left.
  - Examples: brand Michelin + search "205 55" → "Michelin 205 55"; nothing set
  → "" (which the query builder turns into match-all).

  3. Assemble the query params (lines 109–115)
  const params = { search: terms, pageSize: 24, currentPage, sortField: "name",
  sortDirection: "ASC" };
  24 items per page, current page number, sorted by name ascending. (as const
  pins the literal types so they match FetchProductsParams.)

  4. Define applyResult — how a response updates the UI (lines 117–125)
  const applyResult = (res) => {
    setProducts(res.items || []);
    setTotalCount(res.total_count || 0);
    if (res.page_info) setTotalPages(res.page_info.total_pages || 1);
    if (res.items?.length) addKnownBrands(res.items.map((i) =>
  brandOf(i.name))).then(setBrands);
  };
  Pushes the items, total count, and page count into state. It also harvests
  brand names (first word of each product name) to feed the brand list — this
  keeps running even though the brand tabs are currently commented out, so they
  can be switched back on instantly.

  5. Track whether this is the very first load (lines 127–130)
  const isInitial = initialLoadRef.current;
  const finishInitial = () => { initialLoadRef.current = false; };
  This is the flag that controls the full-screen SyncingOverlay — it should only
  appear on the first load, never on later brand/search/page switches.

  6. Cache-first fetch (lines 133–150)
  const cached = await getStorefrontProductsCached(params, { onFresh, onError
  });
  getStorefrontProductsCached does two things at once:
  - Returns whatever is already in IndexedDB for these exact params (assigned to
  cached).
  - Fires the live GraphQL request in the background. When it resolves, onFresh
  applies the fresh data and hides loaders; if it fails, onError hides loaders
  and only surfaces the error if there's nothing already on screen (prev.length 
  === 0).

  7. Decide what to show right now (lines 152–167)
  if (cached && cached.items.length > 0) {
    applyResult(cached);              // instant paint from cache
    setLoading(false);
    if (isInitial) setTimeout(() => setIsSyncing(false), 1200);
  } else {
    setLoading(true);
    if (isInitial) { setIsSyncing(true); setSyncStep("Products"); }
  }
  - Cache hit → paint immediately; only dismiss the overlay (after 1.2s) if it
  was the first load.
  - Cache miss → show the loading state, but only pop the blocking overlay on
  the initial load. For a brand/search/page change with no cache, it keeps the
  current grid visible and fetches quietly in the background.

  The two-phase behavior (key idea)

  For any given search/filter:
  1. Synchronously-ish: returns cached data → instant paint (or shows loader if
  none).
  2. Asynchronously: the live Magento result arrives via onFresh → grid updates
  + IndexedDB is refreshed for next time.

  So typing a search shows cached matches instantly (if any), then swaps in the
  authoritative server results a moment later — no blank screen, no blocking
  loader after the first load.
